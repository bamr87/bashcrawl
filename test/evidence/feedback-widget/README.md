# The feedback button sits clear of the prompt and opens the report dialog — evidence

> **Feature:** `BASHCRAWL-026` · **Scenario:** `verify/scenarios/feedback-widget.yml` · **Result:** **PASS** (2/2 viewports, 18 steps each, no console errors, no sideways scroll) · **Generated by:** `node verify/runner.mjs --by agent` against the production bundle (`make web-bundle`, served by `npm run preview` as `verify/verify.yml` says), 2026-11-20 (UTC)

A returning hero opens the Story door, finds the floating **Improve this page** button above the prompt dock and the footer, and opens the dialog that files a GitHub issue. The button is the fleet feedback widget (`public/fleet-feedback.js`), mounted once by `web/src/chrome/Feedback.tsx`; `AppShell` publishes the dock and footer height as `--bc-bottom-chrome`, and the button sits one offset above it. After the 2026-11 redesign the button is 40 px on the phone (48 px before) and the footer is no longer shown at phone widths (`.bc-footer` is `display: none` there), so on `phone-360` the scenario's footer half has nothing to measure (`footerTop: 0`) and only the dock half is exercised.
