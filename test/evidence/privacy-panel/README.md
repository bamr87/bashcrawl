# A build with no analytics key asks nothing, sends nothing and says so — evidence

> **Feature:** `BASHCRAWL-029` · **Scenario:** `verify/scenarios/privacy-panel.yml` · **Result:** **PASS** (2/2 viewports, 39 steps each, no console errors) · **Generated by:** `node verify/runner.mjs --by agent` against the production bundle (`make web-bundle`, served by `npm run preview` as `verify/verify.yml` says), 2026-11-20 (UTC)

A first-time visitor on a build without a PostHog key. No consent bar is rendered (`.bc-consent` count 0) on the home page or, later, in the Story door. Options, from the gear, carries the row "Privacy — This copy collects nothing"; its Details button opens the Privacy panel, which says "This copy of Bashcrawl has analytics switched off entirely: it sends nothing, and there is nothing to opt out of.", shows no on/off switch, and still lists all 25 product events from `$pageview` to `consent_updated` with their properties. The home page's footer opens the same panel. After a sandbox command, "Skip setup, jump in", skipping the tour and a `pwd` that completes a quest, every entry in the browser's resource timing is on the site's own origin (the `nothing-left-the-site` eval in `report.json` has the count); no URL mentions PostHog, `window.posthog` is undefined, `localStorage` holds only the game's four keys (hero, journal, state, shell), and there is no cookie.
